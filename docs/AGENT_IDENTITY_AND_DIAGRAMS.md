# Agent identity and architecture explanation — 2026-10-09

## Identity

Agent Deck is the confirmed name. The provisional brand label is removed. The current logo uses three offset cassette cases, negative-space gaps and one tape window with small reel hubs; the face-like lower opening has been removed. Colored actors retain the simple stepped silhouette, negative-space eyes and a signal notch. The reader display now shows three smaller connected actors in matte yellow, brick red and leaf green. The original agent-shaped mark is preserved in assets/agent-mark.svg. They are original SVG paths authored for the project; no external mascot or logo graphic is redistributed.

The approved hardware material system remains: upright warm ABS console, inset dark glass, deep cartridge shells, ribs, printed bands and contacts.

## Meaning

Characters indicate model-driven actors. A repeated actor name and color preserve identity across multiple calls. Distinct actors may use the same underlying model. Names accompany colors, so color is not the sole identifier.

Tools/code, retrieval, memory operations, stored data, checks, merge points, human approval and candidate states use separate shapes and icons. Search candidates are data states. The dynamic-team view is an available roster; only the selected specialist acts on a turn.

Worker capacity expands only the phases specified by the runtime contract; managers and final aggregators stay single. Existing stage IDs, predicates, state contracts and termination conditions remain intact. Data connections mean context access and do not imply writes to a retrieval index.

## Interaction

Every cartridge preview uses the expanded explanatory view. The 11 layout families are sequence, branch, fanout, loop, search, retrieval, debate, hierarchy, layers, memory, choice. Default views contain 6–12 nodes depending on mechanism. This is an explanatory view, not a measured execution.

The Wiring tab explains the mechanism, names actors, differentiates control/context connections, describes conditional routes and shows phase controls. Selecting a node by pointer or Enter/Space displays its instruction, purpose, inputs, outputs and connected context. Mobile diagrams use a vertical reading order.

Explanatory data is included in all JSON blueprints and Markdown guides. Model/tool adapters, task-specific dependency graphs, actual search content and instance-message delivery remain runtime responsibilities.
