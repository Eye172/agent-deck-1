# Content and blueprint method

## Identity and counts

A family identifies a mechanism. A wiring type is an editorial structural label. A preset combines a family with a task contract. Version 0.1 contains 64 families, 46 wiring labels and 384 presets.

Six applications differ in inputs, tools, outputs, privacy/memory boundaries, acceptance criteria, failures and examples. A domain adaptation proposes a use; it does not establish an improvement over a simpler baseline.

Complexity is editorial: Basic is a small fixed path; Intermediate adds bounded routing, loops, handoffs or aggregation; Advanced adds planning, evidence correction, durable state or specialists; Expert adds dynamic search, hierarchy, graph structures, tiered memory or distributed execution requirements. These are not measured quality rankings.

## Required content

Each family has original stages, conditional transitions, a tradeoff, references and a runtime contract specifying state fields, an invariant and a failure probe. Each application supplies its own task, example, tool names, artifacts, checks and fixture.

References identify conceptual or engineering bases. Editorial combinations do not imply that a cited author invented every detail.

## JSON 1.0.0

Exports include classification, inputs, description, model placeholders, control stages/edges, runtime contract, adapters, state/memory, policies, outputs, prompts, provenance and evaluation plan.

Node artifacts require stage identity, status, content, evidence references and unresolved issues. Status is passed, partial, failed or blocked. Evidence resolves to accessible sources or actual tool results.

Transition labels are predicates to implement, not executable JavaScript. Expanded diagrams show controller phases, bounded worker slots, illustrative search states and context objects. Task-specific DAG jobs and instance-message delivery remain runtime responsibilities; diagrams are not execution traces.

Model/provider configuration is unresolved. Not every model supports each tool, output format or sampling setting. Tool names are adapter contracts; memory storage is declared separately from domain tools. Gates need validator implementations. Mechanism operations are assigned to stages separately from domain read tools. Stage outputs follow their own instruction, not a scenario artifact chosen by position. Failed stages cannot claim passed artifacts; missing transitions return blocked results. A normal phase exit does not imply task acceptance.

Budgets are starting values. Acceptance, cancellation or any exhausted call, step or time allowance terminates the workflow even when a retry edge exists.

## Exports and customization

JSON and Markdown are generated from the same source catalog. The Blueprint tab changes validated temperature and call/time budgets. Its custom download includes applied settings. Footer links retain the defaults.

Browsing does not send documents or inputs to models. Favorites use browser-local storage. No accounts, API keys or analytics are required.

## Evidence and licensing

Training-specific Self-RAG/Adaptive-RAG parts, Voyager's environment and ReasonMaxxer post-training are not reproduced. Dates and project history are not backdated. Software tests do not establish model performance.

## Extending the collection

Add a stable family and source IDs, then a unique mechanism contract in contracts.mjs. Explain the meaningful difference, required state, stop conditions and failure behavior before adding another name. Regenerate taxonomy/exports and rerun checks.

If copying an implementation later, identify upstream, pinned revision and license, record copied material, and preserve required notices. Attribution alone does not replace license obligations.
